学习安排

1.1 从“写出程序”到“信任数据”

游戏智能体实验最终也要读数据、调用函数、检查错误和统计结果。假设某个 Agent 跑了三局，记录步数为 8、20、12，其中第一和第三局成功。成功率是 2/3，全部局平均步数是 40/3，成功局平均步数是 10。三个数回答不同问题：成功多少、总体花了多少动作、成功时通常多快。

如果程序把超时局删掉再算“成功率”，结果会严重失真；如果没有成功局却将成功步数写成 0，也会让失败系统看起来很快。因此第一份练习先练统计和输入检查。正确的程序设计与实验解释从这里就已相连。

1.2 名称绑定到对象

在 Python 中，赋值让名称绑定到对象。它不承诺复制对象，更不等于 C++ 的所有赋值操作都具有同样语义。

python
a = [1, 2]
b = a
b.append(3)
print(a)  # [1, 2, 3]

a 和 b 指向同一个可变列表。b = [9] 是把 b 重新绑定到另一个列表，不会把 a 改为 [9]。区别在于：前者修改对象，后者修改名称的绑定。

函数参数也是把局部参数名绑定到传入对象。函数内对列表执行 append 会影响调用方看到的对象；函数内把参数重新赋值为新列表，通常不改变调用方那个名称。不要用“Python 总是传引用，所以任何赋值都会影响外部”来理解它。

python
def mutate(items):
    items.append(7)

def rebind(items):
    items = [7]

x = [1]
rebind(x)  # x 仍为 [1]
mutate(x)  # x 变为 [1, 7]

== 通常比较值，is 比较是否同一个对象。检查 None 常写 x is None。不要用小整数或短字符串的缓存行为证明两个值的语义是否相等。

1.3 浅拷贝为什么还会改到原数据

a.copy() 创建新的外层列表，但里面的元素仍然是原来的对象。对嵌套结构尤其要留意：

python
a = [[0], [1]]
c = a.copy()
c[0][0] = 9
print(a)  # [[9], [1]]

可以画两层图：外层 a/c 各自保存两个引用，第一个引用都指向同一个内层列表 [0]。如果只替换 c[0] = [9]，则原 a 不受这一替换影响。需要递归复制时可用 copy.deepcopy，但复制大模型或环境对象并不是无成本、总正确的做法。

与实验的联系：把一份 episode 字典加入多个列表后，后续补字段可能同时改变多个“版本”。保存原始记录时最好立即序列化，派生统计另存，不靠一个浅拷贝冒充不可变历史。

1.4 默认参数和返回值

默认参数表达式在函数定义执行时求值。以下历史列表会跨调用保留：

python
def record(value, history=[]):
    history.append(value)
    return history

如果希望每次未传 history 时创建新列表，使用 None 作为约定：

python
def record(value, history=None):
    if history is None:
        history = []
    history.append(value)
    return history

函数没有 return 时返回 None；list.sort() 原地排序并返回 None，所以 b=a.sort() 并没有得到一个排序后的新列表。使用 sorted(a) 才会返回新的排序结果。

把“读取”“验证”“统计”“保存”分成短函数。统计函数尽量只依赖输入记录并返回新摘要，这样能直接给它三条小记录，而不必先建立文件系统和模型环境。

1.5 容器、循环与复杂度

列表保存有序元素；字典保存键到值的映射；集合适合去重和成员检查；元组常表示固定结构。字典键应满足可哈希条件，不能直接用可变列表当键。变量有类型注解不代表 Python 会自动在运行时检查输入。

for record in records 依次取元素。不要遍历同一列表时随意删除元素，否则位置移动可能跳过数据。通常新建一个筛选后的列表；但对实验失败不能简单筛走，必须先说明统计范围。

列表按位置访问通常 O(1)，成员搜索通常 O(n)；字典与集合的查询通常平均 O(1)，最坏情况及常数开销另论。小规模练习先追求清楚，再避免在每条轨迹内部重复扫描整个数据集。变量名应区分 all_steps 和 success_steps，避免把语义混成一个 score。

1.6 路径、编码和异常

当前工作目录 cwd 与脚本所在目录可能不同。Path("data.json") 相对 cwd 解析；如果数据与脚本绑定，可明确使用 Path(__file__).resolve().parent 构造位置。配置、输入和输出路径最好通过命令行显式给出。

python
from pathlib import Path
import json

path = Path("data.json")
text = path.read_text(encoding="utf-8")
records = json.loads(text)

UTF-8 是文本的编码约定，JSON 是数据结构的表示格式，两者不是一回事。明确编码能减少不同 Windows 和 Python 版本默认行为带来的差异。

FileNotFoundError 表示路径对应文件不存在；json.JSONDecodeError 表示读到了内容，但格式不合要求。不要 except Exception: return [] 把所有错误都变成“没有数据”。读取失败应该可见，否则下游统计可能看起来正常。

遇到 traceback，先看最后一行的异常类型和信息，再回到自己代码里最接近错误的调用位置，打印最少量输入、类型和路径。修复后再构造一个真正触发相同原因的小例子。

1.7 设计一份可靠的记录

一局记录至少包含 episode_id、seed、success、steps、end_reason。success 应是布尔值，steps 是非负整数。Python 中 bool 是 int 的子类，因此仅 isinstance(steps,int) 会接受 True；严格验证可用 type(steps) is int。

空数据集的成功率没有定义，用 None，序列化后为 null。全部失败时，成功局平均步数也是 None；全部平均步数仍可计算。输入错误使用明确的 ValueError，并带记录索引，不能偷偷删除失败数据。终止原因宜单独记，任务成功由明确的评测条件确定，不能一概由“奖励大于 0”猜测。

脚本入口 if __name__ == "__main__": 让文件被导入时不自动执行主流程，便于另一份检查程序导入 summarize 函数。参数解析放在 main 内，统计逻辑放在独立函数里。

一次实验数据是怎样流过程序的

先在纸上拆开四个步骤

一份可靠的统计程序可以拆为读取文件、验证记录、计算摘要、保存结果。读取函数只负责将字节/文本转为Python对象；验证函数负责拒绝不满足数据约定的值；统计函数只计算；输出函数处理显示精度与存储。拆分的目的，是让你能给每一步单独构造最小反例。

如果JSON解析成功，得到的可能是列表、字典、数字甚至null，不能直接认为“文件读出来了，所以数据合法”。同样，"false"是非空字符串，bool("false")为True；盲目类型转换会把明显错误变成错误事实。

从C++经验迁移，但检查语义差别

C++中的auto b=a可能调用拷贝构造；Python中的b=a通常只是新增绑定。C++的const接口可以表达某些只读约束，Python的类型注解并不自动施加同类运行时约束。两种语言都可以写可靠代码，但不能仅凭相似语法猜行为。

python
def append_event(events, event):
    events.append(event)
    return events

history = []
view = append_event(history, {"action": "left"})
view[0]["action"] = "right"
print(history)

输出为[{'action': 'right'}]。append没有复制字典，返回也没有复制列表。这里有两层共享：history与view共享外层列表，列表里又存着一个可变字典。想保存一个时刻的原始观察，可以明确复制需要的字段或立即序列化，而不是仅换一个变量名。

用不变量设计验证

不变量是每条合法记录都应满足的条件。例如episode_id非空且唯一；steps为非负整数；success确为bool；记录不能被重复算入。把这些条件写成函数接口，比程序结尾才“感觉数字不对”更容易定位。

错误信息需要指向记录索引与字段，但不应把用户凭证或不相关文件内容写进日志。教学数据很简单，后面模型请求可能包含敏感上下文，记录范围应与任务一致。

一个完整的核心实现如下；文件读写可复用examples/01_trajectory.py的组织。

python
def summarize_basic(rows):
    if not isinstance(rows, list):
        raise ValueError("rows must be a list")
    for row in rows:
        if not isinstance(row, dict):
            raise ValueError("record must be an object")
        if type(row.get("success")) is not bool:
            raise ValueError("success must be bool")
        steps = row.get("steps")
        if type(steps) is not int or steps < 0:
            raise ValueError("invalid steps")
    good = [r for r in rows if r["success"]]
    n = len(rows)
    return {
        "n": n,
        "success_rate": len(good)/n if n else None,
        "mean_all": sum(r["steps"] for r in rows)/n if n else None,
        "mean_success": sum(r["steps"] for r in good)/len(good) if good else None,
    }

2.1 从一条样本到一批样本

假设每个游戏状态用三个特征描述：到目标的估计距离、是否持钥匙、已探索格子数。单条样本是三维向量 x。一批 N 条样本组成矩阵 X，约定每行一个样本、每列一个特征，形状为 (N,d)。特征必须来自允许观察或合法历史；形状正确不代表信息来源合法。

线性模型 y_hat=Xw+b 中，w 的形状是 (d,)，b 是标量，输出是 (N,)：每条样本一个预测。每个权重描述对应特征怎样线性影响预测，这只是模型结构，并不表示真实世界必然具有线性关系。

text
X: (N, d)
w: (d,)
X @ w: (N,)
b: scalar
prediction: (N,)

2.2 内积、范数和矩阵乘法

向量内积是对应元素乘积之和。x=[1,2]，w=[2,-1]，则 x·w=0。欧氏范数为 sqrt(sum(x_j²))，在这个例子中为 sqrt(5)。内积体现某种方向相关性，但特征单位与尺度会改变其数值，不能自动理解为任务语义相似度。

矩阵乘法是把“行与列做内积”应用于多组数据。若 A 是 (m,k)，B 是 (k,n)，则 AB 是 (m,n)，中间维度 k 要匹配。NumPy 的 @ 表示矩阵乘法，* 表示逐元素乘法或广播后的逐元素乘法。

python
import numpy as np
X = np.array([[1., 2.], [3., 4.], [-1., 1.]])
w = np.array([2., -1.])
print(X @ w + 0.5)  # [0.5, 2.5, -2.5]

NumPy 的一维数组 (d,) 不等同于二维列向量 (d,1)。w.T 对一维数组通常仍为 (d,)，不会自动变成列向量。需要二维列时明确写 w[:,None] 或 w.reshape(d,1)。

2.3 广播规则和静默错误

广播从最右边的维度开始比较：对应维度相等，或其中一个为 1，才可兼容；缺失的前导维度按 1 理解。它通常无需真正复制较小数组，但运算结果本身仍可能很大。

text
(3, 2) + (2,)     -> (3, 2)
(3, 1) + (3,)     -> (3, 3)
(3, 2) + (3,)     -> 不兼容

第二行是常见陷阱。预测为 (N,1)，标签为 (N,)，相减得到 (N,N)，每个预测减去了每个标签，而非只减同一个样本的标签。均值仍能算出一个数，训练甚至可能下降，所以“没报错”和“loss 下降”都不足以证明实现正确。

在计算误差前检查 prediction.shape == target.shape。这里推荐整个线性回归示例统一成 (N,)，进入多输出任务时再明确 (N,k)。不要为了让错误消失随意 squeeze 所有维度，batch 为 1 时可能顺带删掉样本轴。

2.4 axis 是沿哪个方向聚合

对 X=[[1,2],[3,4],[5,6]]，X.mean(axis=0) 得到 [3,4]：跨样本求每列均值，形状从 (3,2) 变为 (2,)。axis=1 得到 [1.5,3.5,5.5]：每行跨特征求均值，形状为 (3,)。axis 指被聚合掉的轴，不是保留的方向。

keepdims=True 保留长度为 1 的轴，有利于明确广播意图。例如逐行归一化可用 (N,1) 的行统计量；逐特征标准化使用 (d,) 或 (1,d) 的统计量。

python
mean = train_X.mean(axis=0)
std = train_X.std(axis=0)
scale = np.where(std < 1e-12, 1.0, std)
train_Z = (train_X - mean) / scale
valid_Z = (valid_X - mean) / scale

这段只用训练集计算统计量，验证集复用。常数列标准差为 0，应按明确规则处理，不能让除零产生无穷和 NaN 后继续训练。

2.5 切片、视图与副本

NumPy 基本切片通常得到视图，可能共享底层存储；花式索引通常生成副本。不要把 Python 列表的切片行为直接套到 NumPy 上。如果 train=X[:100]，原地修改 train 有可能改变 X；若需要独立处理，显式 copy，并说明复制成本。

从损失函数到梯度下降

正文进阶练习
学习安排

对应第 3 周，并在第 5 周用自动微分复习。配套 examples/02_linear_numpy.py。核心问题：一个模型怎样根据误差改变参数？

3.1 先分清输入、参数与目标

在预测 y_hat=wx+b 中，x 是已给定的输入，w/b 是要学习的参数，y 是用于比较的参考值。损失 L 是衡量预测误差的标量。训练通过调整参数降低训练损失；验证用未参与更新的数据观察效果。

最小例子：x=2，y=3，w=1，b=0。预测为 2，误差为 -1。取 L=(wx+b-y)²/2，损失为 0.5。这里除以 2 是为了让导数里的 2 抵消；若定义不除以 2，梯度会相应变成两倍。看到公式不同，先检查约定，不要机械对答案。

3.2 导数、偏导和链式法则

导数描述局部变化率。令 e=wx+b-y，则 L=e²/2。把计算分为参数→预测→误差→平方损失几步，链式法则沿着依赖相乘：

text
dL/de = e
de/dw = x
de/db = 1
dL/dw = e*x = -2
dL/db = e   = -1

偏导表示改变一个参数、其他独立参数保持不变时的局部变化。所有参数的偏导组成梯度。用学习率 eta=0.1 朝负梯度更新：w_new=1-0.1*(-2)=1.2，b_new=0-0.1*(-1)=0.1。新预测为 2.5，损失为 0.125。

这里两个梯度应基于同一组旧参数计算，再一起更新。先改 w、又用新 w 重新计算 b 梯度，是另一种更新程序，不再是刚推导的一次普通梯度下降。

3.3 推到一批样本

令 X 为 (N,d)，预测为 Xw+b，误差 e 为 (N,)。取均方损失的一半：

text
L(w,b) = (1/(2N)) * sum_i e_i^2
e_i    = sum_j X_ij*w_j + b - y_i
grad_w = X.T @ e / N
grad_b = mean(e)

推导每个 w_j 的偏导：只有预测中的 X_ij*w_j 随 w_j 改变，故 d e_i/d w_j=X_ij，再对样本求和。矩阵写法把 d 个相同结构的求和放到一次乘法中，输出 grad_w 为 (d,)。

如果不同样本需要权重，损失和梯度都要按相同权重归一化；若把每条轨迹的 token 平均再求均值，与把所有 token 一起平均，不一定是同一个目标。

3.4 数值梯度检查

不知道自己的手推是否正确，可以使用中心差分：

text
dL/dw_j ≈ [L(w+h*e_j,b) - L(w-h*e_j,b)] / (2h)

e_j 在这里表示第 j 个坐标为 1 的基向量，不是前文误差 e。检查时用 float64 和少量参数，将解析梯度与数值近似比较。h 太大可能使高阶误差增大，太小则有浮点抵消；不要追求 h 无限接近 0。

通常比较绝对误差与相对误差：当真梯度接近 0 时，相对误差分母也接近 0，要有稳定项或绝对容差。配套脚本在固定小例子上核对梯度，而不是靠“训练没报错”判断公式正确。

3.5 为什么负梯度可能降低损失

局部一阶近似 L(theta+delta)≈L(theta)+grad·delta。取 delta=-etagrad，后项为 -eta||grad||²，在足够小的步长和适当光滑性条件下有下降趋势。但近似有范围，神经网络目标也可能非凸，不能由此保证任意学习率都下降或达到全局最优。

对 L(w)=w²/2，梯度为 w，更新后 w_new=(1-eta)w。0<eta<2 时这个一维二次例子会收缩到 0；eta=2 会等幅震荡；eta>2 可能发散。更一般的二次目标收敛范围还依赖曲率，不能把“2”当通用上限。

特征尺度影响曲率：一列数值约 1，另一列约 1000 时，同一个学习率可能在不同方向表现差异很大。标准化常能改善优化条件，但参数变为标准化坐标下的参数，需要正确解释。

3.6 Batch、epoch 与 step

batch 是一次处理的一组样本，epoch 是训练集一次遍历，step 通常指一次参数更新。若 N=1000，batch_size=100，不丢弃样本时一轮约 10 次更新。梯度累积会让多个小批次对应一次更新，采样有放回时“一轮”的意义也要重新约定。

全批量梯度使用整个训练集；SGD 常泛指用小批量估计梯度的更新。Adam 使用梯度的一阶和二阶矩的移动统计进行自适应缩放；它仍需要合理学习率，不能自动修复错误标签或数据泄漏。

基础练习先使用全批量梯度下降观察清楚，再引入随机批次。运行同一个脚本时，只改学习率或步数中的一个，保存配置和结果。观察发散时，记录 NaN/Inf 或损失趋势，不通过删掉坏运行美化结果。

3.7 训练、验证和可解释产物

配套脚本生成带噪声的线性数据，在生成器打乱后划分训练与验证，标准化参数只来自训练集。训练记录的是标准化输入下的参数，因此它们不应直接与原始数据生成权重硬比较。

若 z=(x-mu)/scale，预测为 z·w_z+b_z，则原坐标权重为 w_x=w_z/scale，偏置为 b_x=b_z-sum(mu*w_z/scale)。这说明一个数值看似“不等于真权重”，可能只是坐标约定不同。

本例验证误差用于教学诊断，不是独立封存测试结果。后续若根据验证结果多次挑模型，还需独立测试集。验收时要能手算本章第一步、解释梯度形状、用差分核对，并说明为什么训练误差降低不等于研究假设成立。

反向传播是一张局部导数账单

画出最小计算图

对L=(wx+b-y)²/2，可以拆为u=wx、v=u+b、e=v-y、L=e²/2。前向保存每个中间值；反向从dL/dL=1开始，把“下游传来的梯度”乘“当前运算的局部导数”。当一个变量影响多条路径时，各条贡献相加。

text
w ---- multiply ---- u ---- add ---- v ---- subtract ---- e ---- square/2 ---- L
        /                   /               /
       x                   b               y

x与y是输入/标签，本例不更新它们；w和b是参数。自动微分可以求输入梯度，但“可以求”不意味着训练会更新输入，更新谁取决于优化器管理的参数。

取x=[1,2]、y=[3,5]、w=b=0，损失定义L=sum(e²)/(2N)。旧误差为[-3,-5]，L=(9+25)/4=8.5，dw=(-31-52)/2=-6.5，db=(-3-5)/2=-4。

eta=0.1时，新w=0.65，b=0.4，新预测[1.05,1.7]，误差[-1.95,-3.3]，新L=(3.8025+10.89)/4=3.673125。这里比单样本多了均值分母，也更容易检查你的损失和梯度是否使用同一种约定。

为什么不是先更新w再求b

在旧参数处求出的梯度是一支完整向量。如果先改w，再用新w重新算db，更新点变了。坐标下降或交替优化可以有意义，但需要另一套清楚定义，不能在普通梯度下降代码里无意混入。

梯度检查的正确使用方式

先用很少的样本、float64与固定参数，逐坐标做中心差分。远离ReLU的不可微点，避免随机Dropout改变每次函数值；需要比较的是同一个确定标量函数。一个梯度数值很小的时候，相对误差可能看似很大，应结合绝对误差。

更大模型可检查随机方向：取方向v，比较grad·v与[L(theta+h*v)-L(theta-h*v)]/(2h)。这不能逐项定位所有错误，却可以降低检查成本。不要为了让误差过关随意放宽容差。

一个常见误解：损失下降就证明梯度对

把梯度少除一个N，有时相当于放大学习率，仍然能下降；把错误广播后的损失求导，也可能稳定下降。梯度检查确认“这段代码是不是在求这个损失的导数”，样例与形状检查再确认“这个损失是不是你要的目标”。两种检查互相补充。

import numpy as np

def numerical_grad(fn, theta, h=1e-6):
    theta = np.asarray(theta, dtype=np.float64)
    if theta.ndim != 1 or not np.isfinite(theta).all():
        raise ValueError("invalid theta")
    if not np.isfinite(h) or h <= 0:
        raise ValueError("invalid step")
    result = np.empty_like(theta)
    for j in range(len(theta)):
        delta = np.zeros_like(theta)
        delta[j] = h
        result[j] = (fn(theta+delta)-fn(theta-delta))/(2*h)
    return result

正文进阶练习
学习安排

4.1 随机变量、分布与样本

把一局任务是否成功记为 S，成功为 1，失败为 0。假设真实成功概率为 p，则 S 服从伯努利分布：P(S=1)=p，P(S=0)=1-p。p 是分布参数，一次观测到的 0 或 1 是样本，n 局中成功次数除以 n 是样本成功率。

如果 p=0.6，跑 10 局并不必然成功 6 局。更多独立样本通常有助于降低估计波动，但样本成功率不会随着每次新增任务都单调靠近 p。一次选出的“好种子”也不能代表总体。

独立不等于看起来不同。同一个基础地图的几种颜色变体、同一模型训练种子的多个 checkpoint，可能共享很多误差来源。正式研究需要说明统计单位，例如按基础地图聚合，而不是把所有变体当独立任务。

4.2 条件概率与信息来源

P(A|B)=P(A且B)/P(B)，前提是 P(B)>0。例如 100 局中 40 局有门，10 局同时有门且失败，则 P(失败且有门)=0.1，P(失败|有门)=0.25。

概率链式法则给出 P(y1,y2|x)=P(y1|x)P(y2|x,y1)。语言模型完整输出的概率是逐步条件概率的乘积，不需要假设 token 独立。若三步概率为 0.5、0.8、0.25，整个序列概率为 0.1；长序列连乘容易数值下溢，故常对概率取对数。

信息条件很关键：测试时看不到完整地图，就不能在策略选择时条件于隐藏地图。将评分器知道的答案交给 Agent，会改变被研究的问题。

4.3 期望、方差与不确定性

离散变量的期望 E[X]=sum(p_i*x_i)，方差 Var[X]=E[(X-E[X])²]。对伯努利成功指标，E[S]=p，Var[S]=p(1-p)。若各局独立同分布，样本均值方差为 p(1-p)/n；有关联时不能直接套用这一公式。

观察到 [0,0,1,1] 时均值为 0.5。以 n 为分母的经验方差为 0.25；以 n-1 为分母的无偏样本方差为 1/3。软件默认分母可能不同，写报告时说明采用什么。

置信区间表示一种重复抽样程序的覆盖性质，不能简单解读成“固定真参数有 95% 概率落在这一次区间里”。入门阶段先学会报告分子、分母、任务范围和一个合适区间，不把个位数差异直接写成提升结论。

配套脚本提供二项比例的 Wilson 区间，用于独立伯努利样本的教学示例；它不处理地图分组相关性，也不是自动证明方法更好。配对方法差异需要针对“同一任务两种方法”设计相应分析。

4.4 Logits、softmax 与交叉熵

logits 是实数分数，不是概率。softmax 计算 p_i=exp(z_i)/sum_j exp(z_j)。为了稳定，可先减去最大 z，概率不变。分数 [0,ln(2)] 对应概率 [1/3,2/3]。

若正确类别是第二类，负对数似然损失为 -ln(2/3)≈0.405465。预测正确并不意味着损失为 0：只有给正确类的概率接近 1，损失才接近 0。

对 one-hot 分类目标，交叉熵就是正确类别的负对数概率。PyTorch 的 CrossEntropyLoss 通常接收原始 logits，内部处理 log-softmax；提前 softmax 再传入可能改变目标和数值行为。标签应按接口使用类别索引或规定的概率格式。

temperature T>0 时使用 softmax(z/T)，T 越小通常越集中，越大越平缓。greedy 选择最高分并非普通随机抽样。真实模型还可能有 top-p、工具约束等机制，须核对实际接口。

4.5 监督学习究竟学什么

回归预测连续量，如估计剩余步数；分类预测类别，如是否应开门。线性回归使用线性函数和平方损失；逻辑回归将线性分数通过 sigmoid 映射到二分类概率，通常最小化二元交叉熵。

逻辑回归的名字虽含“回归”，常用于分类。它对参数仍是线性分数，但概率经过非线性映射。MLP 将线性层与非线性激活组合，能够表达更复杂关系。增加容量可能降低训练误差，也可能增加过拟合风险。

没有免费最佳模型。树模型擅长某些表格任务，CNN 利用图像局部结构，RNN/Transformer 处理序列；方法选择要依据数据和目标，而不是名称新旧。本主线先把线性模型和 MLP 学透，再按任务扩展。

4.6 训练、验证、测试的职责

训练集用于拟合模型和数据变换参数；验证集用于选择超参数、早停和方案；测试集用于方案冻结后的最终评估。反复查看测试集挑提示或技能，测试集就逐渐成为开发数据。

先划分，再在训练数据上拟合标准化、特征选择和缺失值处理。验证/测试使用相同变换。虽然标准化没有用标签，提前用全数据均值仍让测试分布信息进入模型构建过程。

划分单位要贴近泛化目标。同一条长轨迹切出的相邻片段随机分到两侧，模型可能只是记住上下文；同一地图的轻微变体跨训练/测试，也未必能支持跨地图家族迁移。需要时按任务、地图或生成模板分组划分。

4.7 准确率、成功率与成本

若 100 个分类样本只有 5 个正类，全预测负类也有 95% 准确率，但正类召回率为 0。混淆矩阵能暴露这种现象；精确率分母是预测为正的数量，召回率分母是真正为正的数量，分母为 0 时需要明示处理约定。

游戏任务常同时报告成功率、全部任务步数、成功任务步数、超时、无效动作和模型调用消耗。失败往往耗尽预算，只看成功任务成本会低估总体支出。技能调用一次可能展开成十几个原始动作，不能按“一次技能=一步”与逐步策略直接比较。

同一批任务跑两个方法能形成配对观察。对任务 i 定义 d_i=success_B_i-success_A_i，均值是成功率差。独立样本多种子、配对任务、训练随机性各自带来的变化应分开记录。

一张二分类混淆矩阵

假设100个任务中20个属于应当触发技能的正类。系统触发了15次，其中12次确实应该触发。于是TP=12、FP=3、FN=8、TN=77；准确率89%，精确率12/15=80%，召回率12/20=60%。这些数字描述不同错误代价。

平均数也有选择

两个任务家族分别成功9/10与1/2，合并微平均为10/12≈83.33%；先求各家族成功率再宏平均为(90%+50%)/2=70%。前者按任务数量加权，后者给每个家族相同权重。报告时写清家族大小，不能只挑更漂亮的一种。

一套实际划分流程

先收集任务元数据与基础地图ID；按基础组划分开发和冻结测试；仅在训练子集拟合预处理；用开发结果选择学习率、提示或技能；固定配置后运行测试；若发现评分器漏洞，修复时要说明测试已经受到检查，必要时另设新测试。

训练、验证和测试不一定都必须以固定百分比分配。数据很少时可用适当的分组交叉验证，但每折仍应只在该折训练部分拟合变换。连续轨迹、同一人的记录、相同地图变体都可能需要分组。

不确定性从哪里来

测试任务的抽样、训练种子、模型采样、环境随机性是不同来源。十次重复同一个任务主要帮助观察该任务上的采样波动，不能变成十个不同任务。设计重复时先决定自己想估计哪一种变化。

配对比较对每个任务计算B-A，再按任务组汇总。若B只多成功一个任务，要看它是否集中于特定家族、是否靠更多调用、是否在其他任务退化。统计检验不能替代公平的信息与预算条件。

如何写一句可信的结果描述

可以写“在固定的10个开发任务上，B比A多成功1个，额外调用量为多少；这是小规模开发观察，尚未验证任务组合迁移”。不要把这个结果写成“显著提升泛化能力”。后者需要更充分设计与证据，也需要核对统计意义与实际意义。

def binary_metrics(truth, pred):
    if len(truth) != len(pred):
        raise ValueError("length mismatch")
    if any(type(v) is not int or v not in (0,1)
           for seq in (truth,pred) for v in seq):
        raise ValueError("expected binary integers")
    tp = sum(t==1 and p==1 for t,p in zip(truth,pred))
    fp = sum(t==0 and p==1 for t,p in zip(truth,pred))
    fn = sum(t==1 and p==0 for t,p in zip(truth,pred))
    tn = len(truth)-tp-fp-fn
    ratio = lambda a,b: a/b if b else None
    return dict(tp=tp,fp=fp,fn=fn,tn=tn,
                accuracy=ratio(tp+tn,len(truth)),
                precision=ratio(tp,tp+fp),recall=ratio(tp,tp+fn))

5.1 张量、类型和计算图

tensor 可视为带形状、类型、设备和自动微分信息的多维数组。浮点参数常使用 float32；类别索引、token ID 常使用整数 long。device 表示 CPU 或其他设备。形状对得上但类型或设备不兼容，运算仍会失败。

requires_grad=True 告诉自动微分跟踪相应张量的可微计算。一次 forward 会建立与运算相关的计算图，backward 沿图使用链式法则累计梯度。它不需要用很小步长反复扰动每个参数，因此与数值差分的计算方式不同。

python
import torch
w = torch.tensor(1.0, dtype=torch.float64, requires_grad=True)
b = torch.tensor(0.0, dtype=torch.float64, requires_grad=True)
loss = (2*w + b - 3).square() / 2
loss.backward()
print(w.grad.item(), b.grad.item())  # -2.0, -1.0

这与第 3 章手算一致。自动微分准确实现的是你实际写出的计算图，不会判断这个图是否对应正确研究目标。若预测与标签广播错了，梯度可能非常“正确”地优化一个错误损失。

5.2 参数、模型和 forward

nn.Module 管理子模块、参数和训练/评估状态；forward 定义输入到输出的计算。一个小 MLP 可以写为：

python
model = torch.nn.Sequential(
    torch.nn.Linear(2, 16),
    torch.nn.ReLU(),
    torch.nn.Linear(16, 2),
)

输入为 (B,2)，第一层输出 (B,16)，激活不改形状，最后输出 (B,2) logits。Linear(2,16) 的可学习权重形状为 (16,2)，另有 (16,) 偏置，参数数目 216+16=48；第二层为 162+2=34，总计 82 个。

ReLU(x)=max(0,x) 逐元素引入非线性。如果所有层都是线性且没有中间非线性，多层复合仍只是一个线性/仿射映射，表达能力不会因堆叠而自动增加。

5.3 数据集、批次与标签

Dataset 负责给定索引返回样本，DataLoader 负责批次、打乱等组织。批次训练能在计算效率与梯度噪声之间取得折中；批次大小不是越大越好，样本分布和优化设置也会影响结果。

本例生成二维点，按两个坐标乘积的符号划为两类，属于 XOR 风格关系。点在同号象限为一类，异号为另一类。原始输入下单条直线无法完美分开所有象限，小 MLP 可学习非线性边界。

生成器、训练划分和标准化都固定记录。标签在本例是已知教学规则，不能据此认为发现了真实世界规律。新点上的验证只针对同一教学生成分布。

5.4 五步循环逐行解释

python
model.train()
for inputs, labels in loader:
    optimizer.zero_grad(set_to_none=True)
    logits = model(inputs)
    loss = loss_fn(logits, labels)
    loss.backward()
    optimizer.step()

第一步清除上一次更新留下的梯度。第二步前向计算得到预测分数。第三步将分数与标签压成标量损失。第四步计算参数梯度。第五步由优化器更新参数。

backward 默认会累积到参数 .grad，因此连续两个小批次都 backward 而不清零，会把梯度相加。有意进行梯度累积时要管理归一化、更新频率等，不能和忘记清零混淆。set_to_none=True 令梯度设为 None，优化器与零张量在某些边界上的语义也有差异，入门按明确循环使用。

5.5 eval 与 no_grad 是两件事

model.eval() 改变 Dropout、BatchNorm 等受模式影响层的行为；torch.no_grad() 控制是否记录梯度图。评估通常同时使用：

python
model.eval()
with torch.no_grad():
    logits = model(valid_X)
    prediction = logits.argmax(dim=-1)

仅 eval 不会禁用自动微分；仅 no_grad 不会把 Dropout 切到推理模式。即使本例没有这两种层，也应理解两种机制，否则换一个网络时很容易出问题。

每批大小不同，计算整套平均损失时应按样本数加权。直接对各批平均损失再平均，会让最后一个小批次与完整批次有相同权重。记录指标前先明确分母。

5.6 怎样诊断“没有学会”

先检查输入、标签、shape、dtype 和损失是否有限；再用极小训练子集尝试拟合，确认实现具有基本学习能力。极小集拟合成功只是工程诊断，不能证明泛化。

如果训练和验证都差，可能存在实现错误、容量不足、学习率不合适或数据本身难；如果训练很好、验证差，可能过拟合或分布变化，也可能是验证流程不一致。不要看到“验证差”就只增加层数。

先把标签分布和一个 batch 打印出来；检查 loss 是否错误地 softmax 两次；检查参数是否真的在 optimizer 中；比较更新前后的一个参数；检查梯度是否 None、全 0 或爆炸。每次只修改一个关键因素，并保留失败记录。

5.7 保存与加载

state_dict 保存参数和模型缓冲区，不是完整实验。至少还需要模型配置、输入标准化、标签约定和依赖版本。配套脚本保存这些必要推理信息，重建相同结构后加载，比较加载前后的 logits。

恢复训练还常需要 optimizer、调度器、步数和随机状态；“加载后推理一致”不等于“训练能精确续跑”。只加载自己生成或可信来源的文件，并核对当前 PyTorch 加载接口。示例使用兼容的 state_dict 加载方式，不下载外部 checkpoint。

5.8 SGD、Adam 与正则化的入门地图

SGD 依据当前梯度更新，动量会积累方向信息；Adam 还维护梯度平方的移动统计。weight decay 与 Dropout 等通过不同机制约束训练。普通 L2 惩罚与某些优化器下的解耦权重衰减不能无条件视作同一种更新。

先理解学习率、batch、模型容量和数据划分，再逐步比较优化器；不要同时改五个设置。早停根据验证表现选训练阶段，最终仍需要独立测试。优化器更复杂并不免除梯度检查。

对应第 7 周，建议分三次学习。本章解释为什么模型结构会对数据形式做假设；不要求训练完整 ResNet 或大型视觉模型。

6.1 全连接层为什么不总合适

把 H×W 图像摊平成向量再接 Linear，会给每个位置独立参数，空间上的相邻结构被隐藏在编号里。卷积用同一小核在不同位置计算，使局部模式检测共享参数。这个结构偏好对图像常有帮助，但并不意味着任何数据都应该卷积。

图像常约定形状为 (B,C,H,W)，B 是批次，C 是通道。MiniGrid 默认观察里的 image 字段未必是 RGB 照片，可能是物体/颜色/状态的离散编码；不可仅凭“image”名字就把三个通道当红绿蓝。

6.2 手算一个二维卷积

神经网络常把不翻转卷积核的互相关也称卷积。取输入 I 和核 K：

text
I = 1 2 3       K = 1 0
    4 5 6           0 -1
    7 8 9

无填充、stride=1 时，左上窗口输出 11+20+40+5(-1)=-4，其余三个窗口也为 -4，输出是 2×2。若输入尺寸 H，核大小 k，padding p，stride s，dilation=1 时输出高度为 floor((H+2p-k)/s)+1。

对 C_in 个输入通道和 C_out 个输出通道，二维核参数量为 C_outC_ink_h*k_w，若有偏置再加 C_out。各输入通道的局部加权和汇成一个输出通道，不是分别卷积后随意拼接。

池化在局部区域聚合，例如最大池化保留局部最大值，改变空间分辨率而通常不引入卷积核那样的可学习参数。空间细节也可能被丢掉，导航任务中要检查这种损失是否可接受。

6.3 残差连接

残差块写作 y=x+F(x)。它让网络学习相对于输入的改变量，并给梯度传播提供额外路径。不能因此声称深网络永远不会梯度消失或一定更优。

python
class ResidualBlock(torch.nn.Module):
    def __init__(self, width):
        super().__init__()
        self.net = torch.nn.Sequential(
            torch.nn.Linear(width, width),
            torch.nn.ReLU(),
            torch.nn.Linear(width, width),
        )
    def forward(self, x):
        return x + self.net(x)

加法两路应有一致的目标形状。如果 F 把 (B,8) 变成 (B,16)，捷径分支可以用 Linear(8,16) 投影，或改变主分支保持 8。依赖意外广播“凑上”形状会改变模型语义。

BatchNorm 依赖批次统计和运行统计，LayerNorm 通常对每个样本的指定特征维度归一化。两者都不是第 2 章的数据预处理标准化，计算位置和训练/推理行为不同。

6.4 RNN 如何携带历史

最简单的递归状态更新可以写成：

text
h_t = tanh(W_x*x_t + W_h*h_(t-1) + b)

x_t 是当前输入，h_(t-1) 是已有历史的压缩表示，h_t 用于输出和下一步。若输入维度 d、隐藏维度 h，则 W_x 为 (h,d)，W_h 为 (h,h)。参数在时间步之间共享。

设一开始观察到“钥匙在左”，之后进入两条看起来相同的走廊。只看当前画面无法区分，历史状态可能帮助决策。但 RNN 不保证保留全部信息，长序列训练也可能出现梯度衰减或爆炸。LSTM/GRU 通过门控结构改善某些问题，仍需实验验证。

跨时间反向传播把整个时间展开为共享参数的计算图。在线运行时有时要在片段边界 detach 隐藏状态，切断不需要继续反传的历史；这会改变训练依赖长度，不能无意中每步 detach 后还声称学到了长程依赖。

6.5 表示与任务之间的关系

模型观察不是世界本身。离散符号、像素、文本描述分别保留不同信息，预处理可能引入人工先验。把局部网格编码成文字能降低感知负担，但可能也把位置关系预处理好了。报告必须说明观察转换做了什么。

后面 ViT 把图像切成 patch 再形成序列，VLM 将视觉表示与语言机制结合，VLA 还包含动作输出。先理解 CNN 的局部共享、RNN 的顺序记忆、Transformer 的注意力，再看这些组合会更清楚。

模型结构编码了哪些假设

先做参数账本，再谈模型大小

Linear(2,16)有216+16=48个参数；一个3输入通道、8输出通道、3×3核且含偏置的卷积有8333+8=224个。卷积参数数目不随图像宽高直接增加，因为同一个核在空间位置共享；但中间激活的内存和计算量仍随空间尺寸变化。

参数少不保证任务更适合，参数多也不保证效果更强。结构选择要看输入是否确有局部性、顺序性以及需要保留的精细信息。MiniGrid物体编码不是自然图像RGB，整数编码距离也不一定具有颜色相似度含义。

卷积尺寸逐步算

输入(B,3,8,8)，卷积核3×3、stride=1、padding=1、输出通道8，则空间尺寸仍为8×8，输出(B,8,8,8)。若接2×2、stride=2池化，输出(B,8,4,4)。将其flatten后是(B,128)，后续Linear的输入维度应为128，不是8。

text
输入图像:       (B,3,8,8)
Conv3x3:        (B,8,8,8)
Pool2x2:        (B,8,4,4)
Flatten:        (B,128)
Linear(128,16): (B,16)

残差的梯度直觉

对标量简化y=x+F(x)，dy/dx=1+F'(x)。恒等路径贡献了一个1，使梯度不必全依赖F的乘积路径；真实多维网络用雅可比表达，仍不能据此保证所有方向都稳定。BatchNorm、初始化、优化器和结构也有作用。

历史状态不是整个历史的无损副本

RNN把新输入和旧隐藏状态组合成固定维向量。它可能压缩掉之后需要的细节。显式记忆表则保存特定事件或对象，但需要更新、去重和失效规则。对于“之前见到钥匙位置”的任务，记录对象位置可能更容易检查；对复杂像素序列，学习表示有其他优势。

学习时画两次更新，把共享参数圈出来。若每次时间步都创建新的Linear，就没有实现预期的时间共享；若每步把隐藏状态重设为0，就没有利用跨步历史。

微型实验应该改什么

只比较有无残差时，要保证尽量接近的宽度、数据、训练预算和初始化方式，并记录增加的投影参数。只换一个因素是诊断起点；当结构同时改变容量和信息路径时，应明确这些变化，不能仅凭结果把原因归到“残差”这个名称。

import numpy as np

def corr2d_valid(image, kernel):
    image = np.asarray(image, dtype=float)
    kernel = np.asarray(kernel, dtype=float)
    if image.ndim != 2 or kernel.ndim != 2:
        raise ValueError("expected two matrices")
    H,W = image.shape
    h,w = kernel.shape
    if h==0 or w==0 or h>H or w>W:
        raise ValueError("invalid kernel size")
    result = np.empty((H-h+1,W-w+1))
    for i in range(result.shape[0]):
        for j in range(result.shape[1]):
            result[i,j] = (image[i:i+h,j:j+w]*kernel).sum()
    return result

MDP、价值与动态规划

正文进阶练习
学习安排

对应第 8 周。配套 examples/05_decision.py。从单次预测转向连续行动时，当前动作会改变未来观察与机会，因此不能只优化眼前分类准确率。

7.1 描述一个决策问题

MDP 常由状态集合 S、动作集合 A、转移/奖励分布、折扣率等组成。状态应包含预测未来所需的信息；Markov 性的直觉是：在给定当前状态和动作后，早期历史不再提供额外的环境转移信息。

使用时序约定：处于 S_t，选 A_t，环境产生 R_(t+1) 和 S_(t+1)。策略 pi(a|s) 给出状态下选动作的概率。策略是决策规则，价值是该规则或动作的长期收益估计，二者不同。

如果只观察局部画面，环境可能仍是 MDP，但智能体可见输入未必足以当作完整状态。这是下一章部分可观察问题的起点。

7.2 回报和价值

折扣回报 G_t=R_(t+1)+gammaR_(t+2)+gamma²R_(t+3)+...。gamma 控制后续奖励的折扣；无穷时域有界奖励且 gamma<1 时，这种和有良好界限。有限回合可在合适条件下使用 gamma=1。

若之后奖励依次为 0、1、2，gamma=0.5，则 G=1。价值 V_pi(s)=E_pi[G_t|S_t=s]，动作价值 Q_pi(s,a)=E_pi[G_t|S_t=s,A_t=a]。期望同时包含策略与环境可能的随机性。

动作“先绕路拿钥匙”可能即时没有正奖励，却使未来开门成为可能。只对当前奖励贪心的策略可能到不了目标，这就是长期规划的意义。

7.3 Bellman 关系来自把第一步拆出来

把 G_t 写成 R_(t+1)+gamma*G_(t+1)，再对下一步取期望，得到固定策略的价值递推：

text
V_pi(s) = sum_a pi(a|s) *
          sum_(s',r) P(s',r|s,a) * [r + gamma*V_pi(s')]

真正终止后的未来回报按约定为 0。对最优价值，把固定策略的动作平均替换成取最大：

text
V_star(s) = max_a sum_(s',r) P(s',r|s,a)
                       * [r + gamma*V_star(s')]

这不是“把每步奖励最大化”，而是在每个动作的即时回报加未来价值上选择。有限折扣 MDP 的标准条件下，Bellman 最优算子具有收缩性质，支持迭代求解；具体证明可在后续 RL 教材深入。

7.4 一条五状态走廊

状态为 0、1、2、3、4，4 是目标。动作左/右使状态增减一格，边界处停留。到达 4 的那一步奖励为 1，其余非终止移动奖励为 -0.01；gamma=0.9，终止状态值为 0。

最优时从 3 向右直接成功，V*(3)=1。从 2 向右后仍未终止，得到 -0.01+0.9*1=0.89。从 1 为 0.791，从 0 为 0.7019。注意到达目标的转移奖励是 1，不是 1 再叠加 -0.01；不同奖励约定会得到不同数值。

这个例子里向左在边界可能自环，仍有步代价和折扣。只有完整模型和最优性推理才支持“向右最好”，不是因为位置编号大的动作天然更优。

7.5 策略评估、策略改进和价值迭代

策略评估固定 pi，迭代求该策略价值；策略改进依据当前价值对动作进行选择；反复交替形成策略迭代。价值迭代则在每次备份时直接取 max，逐步逼近最优价值。

text
初始化 V(s)=0
重复：
    对每个非终止状态 s：
        new_V(s)=max_a [r(s,a)+gamma*V(next(s,a))]
    检查 new_V 与 V 的差异
    V = new_V

伪代码采用同步更新：一轮内都读旧 V。原地更新也可以构成另一种迭代方案，但手算与程序比较时要统一约定。停止阈值是数值迭代标准，不是自动给出任务成功率的统计证明。

7.6 规划与学习的分界

价值迭代在这里直接使用全部状态的转移和奖励，所以属于已知模型下的规划。Q-learning 以后只根据采样到的转移更新，不要求事先枚举完整转移模型。

规划也可能使用从数据学到的模型，学习也可能与规划结合。关键是说明算法拥有何种信息，而不是简单把一个名字归到固定阵营。

示例走廊很小且完全可观察，用来验证递推和更新。它不能证明在局部观察迷宫、连续控制或真实大模型游戏任务上有效。通过本章的标准是能独立画状态图、写奖励约定、手算价值，再与脚本核对。

练习：把每步代价改为 -0.1，重新计算 0 到 3 的最优价值；再改 gamma=1，讨论有限到达目标的路径。若存在不终止且总奖励不收敛的轨迹，不能直接照搬折扣问题的保证。

参考：Sutton & Barto《Reinforcement Learning: An Introduction》第二版，出版社入口。本章走廊、奖励与数值均为自建教学设置。

从一棵两层决策树理解Bellman备份

先不用公式，枚举两步

在状态s选动作a，第一步奖励为r，可能到达s1或s2。到达哪一个状态有概率分布，各自后面还有回报。动作的长期价值是“本步奖励，加上按转移概率加权的未来价值”，再考虑折扣。Bellman关系就是把这个结构写成递推。

假设动作a立即奖励0，以0.5概率到价值2的s1，以0.5概率到价值0的s2，gamma=0.9，则Q(s,a)=0.9*(0.52+0.50)=0.9。动作b立即奖励0.8后终止，Q(s,b)=0.8。眼前b奖励高，长期却是a更高。

固定策略的平均与最优策略的最大

若策略以一半概率选a、一半选b，V_pi(s)=0.85；若允许选择最优动作，V_star(s)=0.9。把策略评估中的动作平均误写成max，就从评估某个策略换成了优化控制问题。

为什么终止状态值为0仍能得到目标奖励

本讲义把成功奖励放在进入目标的转移上，因此Q=r+gamma*0仍能拿到1。如果同时把目标V设为1，又在进入时给1，就可能重复计入奖励。另一种奖励放置也可定义，但代码、公式和手算必须一致。

同步更新的一轮不是一次完整求解

五状态走廊从V全0开始，第一轮只有紧邻目标状态能看到奖励1；第二轮信息再传播一格。若从靠近目标向起点原地扫描，一轮可能把信息传播得更远。这是更新顺序不同，不等于两者计算了不同的任务。

python
def backup(reward, next_value, gamma, terminated):
    future = 0.0 if terminated else gamma * next_value
    return reward + future

先测reward=1、next_value=100、terminated=True仍应返回1；再测非终止返回1+gamma*100。外部截断是否属于真正终止，需要由任务约定决定，不能在这个函数里凭“回合停了”猜。

import math

def bellman_action(outcomes, values, gamma):
    if not math.isfinite(gamma) or not 0 <= gamma <= 1:
        raise ValueError("invalid discount")
    probs = [row[0] for row in outcomes]
    if not probs or any(not math.isfinite(p) or p<0 for p in probs):
        raise ValueError("invalid probabilities")
    if not math.isclose(sum(probs),1.0,abs_tol=1e-9):
        raise ValueError("probabilities must sum to one")
    total = 0.0
    for p, successor, reward, done in outcomes:
        future = 0.0 if done else gamma*values[successor]
        total += p*(reward+future)
    return total

正文进阶练习
学习安排

对应第 9–10 周。配套 examples/05_decision.py；真正 MiniGrid 接口另见第 11 章。目标是区分随机探索、从经验学习、已知模型搜索和基于历史的决策。

8.1 为什么要探索

多臂老虎机中，每个动作有未知奖励分布。只利用当前估计最高的动作，可能永远错过尚未充分尝试的好动作。epsilon-greedy 以 epsilon 概率随机选动作，其余时间按当前价值贪心；这是简单的探索规则，不是所有任务的最佳探索方法。

随机动作、随机初始化、随机数据划分是不同随机来源。训练时使用探索，不等于评测也必须沿用相同 epsilon。评测究竟测随机策略的平均表现还是确定性贪心策略，必须事先说明。

8.2 MC 与 TD 的区别

Monte Carlo 方法利用采样得到的完整回报更新；TD 用一步奖励加后继价值估计作为目标，称为自举。一个简单状态值更新为 V(s)←V(s)+alpha*[r+gamma*V(s')-V(s)]。

MC 需要等到所需回报可计算，TD 可在一步后更新，但使用了当前价值估计。两者有不同偏差、方差和适用条件，不能仅凭“更新快”断言 TD 总更好。

8.3 Q-learning 的一步

Q-learning 记录每个状态动作的值，不要求事先知道完整转移模型。标准表格更新：

text
target = r                         # 真正终止
target = r + gamma*max_a' Q(s',a')  # 非终止
Q(s,a) += alpha * (target - Q(s,a))

取 Q=2、r=1、gamma=0.9、max Q'=4、alpha=0.1。非终止目标为 4.6，更新为 2.26；真正终止目标为 1，更新为 1.9。这两个数的差别来自是否存在后继回报。

Q-learning 的行为策略可使用 epsilon-greedy，但目标取后继最大值，属于 off-policy 的典型例子；SARSA 则使用行为实际选到的后继动作值。表格收敛通常还需要足够访问和合适学习率等条件，本例固定少量回合只是机制练习，不能引用一般定理保证任意运行收敛。

配套五状态走廊通过采样更新 Q，再从起点执行贪心策略。得到四步到目标，只能说明在这个简单环境上学到了对应动作；不能说明能够解决局部观察迷宫。

8.4 终止、截断和 reset

Gymnasium 的 step 返回 observation、reward、terminated、truncated、info。任务真正终止时，后续价值通常按终止约定为 0；外部时间限制截断时，任务本身可能仍可继续，价值目标通常仍应自举。

有限时域任务自己定义的截止可属于真正终止；若剩余时间影响最优行动，观察/状态需要正确表示时间。自动 reset 封装还可能返回下一回合初始观察，训练代码必须使用正确的最终后继观察，不能串局。

因此更新掩码不能随意用 not(terminated or truncated)。但“一切时间限制都应自举”也不正确，先区分时间限制是否属于任务本身。具体接口以当前封装文档为准。

8.5 BFS 与学习解决不同信息条件下的问题

若已知网格可通行关系，每步成本相同，BFS 可用队列按距离逐层扩展，找到最少边数路径；边成本不同时通常需要 Dijkstra 等方法。BFS 不需要训练数据，但需要可用的邻接关系。

text
queue <- [start]
parent[start] <- None
循环直到队列为空：
    node <- 队首弹出
    若 node 是目标：结束并回溯 parent
    对每个合法邻居：若未访问，记录 parent 并入队

游戏动作可能包含朝向、转弯、取钥匙、开门。只以 (x,y) 作为状态做最短格子路径，不一定对应最少原始动作；状态可能需扩为 (x,y,direction,inventory,door_state)。为了教 BFS，可以先简化任务，但报告要写明简化。

如果地图不可见，不能直接把环境内部全图读给搜索器。可在已观察的自由格子上规划，到未知边界时探索；完整地图 BFS 只能作为明确标记的信息上界或环境调试工具。

8.6 部分观察与记忆

局部观察 o_t 可能对应多个真实状态，单看当前观察无法决定最优动作。历史 h_t=(o_0,a_0,...,o_t) 提供额外信息。理论上可用 belief 表示对隐藏状态的概率分布；实际系统常用已探索地图、事件列表或神经网络隐藏状态近似。

记忆必须标明“知道什么、何时观察到、是否可能已经变化”。把未见格子填为可通行是未经证据的假设；把旧门状态永久当作现在状态，也可能导致错误。状态估计和规划是不同模块，错误来源要分开诊断。

任务“找钥匙再开门”常涉及前置条件：没有钥匙时尝试开锁可能失败。技能不应只保存动作序列，还可声明前提、终止条件和预期效果。先在小网格上检查这些逻辑，再讨论自动技能发现。

8.7 从教学到可比较实验

随机策略是接口和记录的检查起点；已知模型规划器是信息条件明确的参照；学习策略利用训练轨迹；LLM Agent 则还包含模型推理和工具上下文。比较时要写清每种方法看到了什么、用了多少数据和动作。

练习：手算两次不同 alpha 的 Q 更新；在走廊中加入外部截断，指出目标应使用哪个后继；设计两个局部观察相同但历史不同的状态，说明一条合法记忆如何帮助决策。

参考：Gymnasium 时间限制说明、Env API。RL 概念可结合 Sutton & Barto 第二版进一步阅读。

一条轨迹里有两种策略

行为策略与目标策略

Q-learning训练中以epsilon-greedy产生动作，叫行为策略；更新目标中的max对应贪心选择，体现了目标策略。它们可以不同。SARSA使用实际采样到的下一动作Q值，因此更直接反映当前行为策略。

这不意味着Q-learning可以无视数据覆盖。一个动作从未尝试，表格里它的值就没有充分证据更新。一般收敛结论有访问、学习率等条件，固定跑600回合只是教学设置。

学习率决定怎样融合证据

更新Q_new=(1-alpha)Q_old+alphatarget。alpha=0.1时旧估计占0.9，新的目标占0.1；alpha=1时直接使用本次目标。若环境随机，直接覆盖会有很大波动；alpha很小则适应较慢。后继Q本身也在变化，因此TD目标不是静态标签。

BFS里的状态到底是什么

二维位置足够解决“已知静态四邻居网格”的最短格子路径。若动作包含转弯、开门和钥匙，位置相同但朝向或背包不同，会有不同合法动作和未来代价。你可能需要状态(x,y,direction,has_key,door_state)。把这些状态合并，搜索器可能给出不可执行路线。

POMDP的最小反例

先让Agent在起点看见红或蓝提示，之后进入画面完全相同的路口；红应左转，蓝应右转。如果不保存提示，任何仅依赖当前画面的确定性策略都会对两种情况采取同一动作。这个反例不依赖复杂网络，就能证明当前观察不够。

一条可检查记忆可以是last_cue='red'，并记录它来自哪一步观察。直接读取环境中的隐藏正确分支，不是记忆。对于会改变的世界还要标明时间与不确定性，不能让旧知识自动变成当前真值。

收集截断与任务失败分开记录

训练器为了控制时长在30步停止采样，不一定代表环境任务真正失败；日志应同时保留环境terminated/truncated和额外的外部预算原因。训练目标、评测成功标准、收集停止标准是相关但不同的约定。

实践时在一条轨迹里逐项指出：行为动作如何选、学习目标如何算、哪些观察可见、何时停止。做到这一点再扩展到大模型Agent，会少很多难以追踪的误解。

from collections import deque

def bfs_path(grid, start, goal):
    if not grid or not grid[0] or any(len(r)!=len(grid[0]) for r in grid):
        raise ValueError("expected nonempty rectangular grid")
    H,W = len(grid),len(grid[0])
    valid = lambda p: 0<=p[0]<H and 0<=p[1]<W and grid[p[0]][p[1]]==0
    if not valid(start) or not valid(goal):
        raise ValueError("invalid endpoint")
    queue,parent = deque([start]),{start:None}
    while queue:
        node = queue.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]

            if valid(nxt) and nxt not in parent:

正文进阶练习
学习安排

对应第 11–12 周。配套 examples/06_attention.py 和 examples/07_tiny_lm.py。核心是理解表示、依赖方向、训练目标和生成过程，而不是背模型名称。

9.1 从 token 到向量

tokenizer 将文本变成 token ID 序列。真实 tokenizer 的切分单位不一定是一字或一词，也不是字符串长度。embedding 表把每个 ID 映射为 d_model 维向量；ID 是索引，向量是可学习表示，不能把 ID 的数值大小当作语义大小。

批次 token IDs 形状为 (B,T)，embedding 后为 (B,T,D)。位置表示用于区分顺序，否则不带位置信息的自注意力结构本身无法按通常方式识别排列次序。位置机制有多种，本例使用简单可学习位置 embedding，不实现所有现代方案。

9.2 Q、K、V 在算什么

对输入 X 做三个可学习线性映射得到 Query、Key、Value。对每个 query，与各 key 算相容分数，再对 value 做加权求和：

text
Q = X W_Q, K = X W_K, V = X W_V
scores = Q K^T / sqrt(d_k)
weights = softmax(scores, axis=key_position)
output = weights V

Q、K 为 (B,T,d_k)，scores 为 (B,T,T)，V 为 (B,T,d_v)，输出为 (B,T,d_v)。分数矩阵的行对应 query，列对应 key；softmax 沿每行的 key 轴归一化。

缩放 sqrt(d_k) 是为了控制常见独立分量假设下点积分数随维度增长的尺度。它不是把注意力自动变成概率正确的语义推理，也不能解释每个头一定“负责某个概念”。

9.3 两个位置的手算

取 d_k=1，Q=[1,2]，K=[1,0]，V=[10,20]。无 mask 时第一个 query 分数为 [1,0]，权重约 [0.731059,0.268941]，输出约 12.689414。第二行分数 [2,0]，输出约 11.192029。

加自回归因果 mask 后，第一个位置不能看第二个 key，所以权重变成 [1,0]，输出为 10；第二个位置仍可看两个位置，输出不变。这个例子展示的是信息流限制，不是模型已经学会语言。

配套脚本还改变后续输入，确认较早位置的输出保持一致。这种因果性检查比只看权重矩阵形状更有意义。

9.4 因果 mask 与 padding mask

因果 mask 禁止位置 t 使用未来位置；padding mask 禁止把补齐占位当有效内容。两者解决不同问题。在分数中给不允许位置设很小值或 -inf，再 softmax，使其权重为 0。

不同库的布尔 mask 有时以 True 表示“禁止”，有时表示“允许”，必须查看实际函数约定。本讲义的手写版本直接对未来分数填 -inf，避免名称带来的混淆。每行至少有一个合法位置，否则全 -inf 的 softmax 可能产生 NaN。

9.5 从单头到 Transformer

多头注意力在多个表示子空间计算注意力，再合并输出。标准 Transformer 块还含逐位置前馈网络、残差、归一化等。层数、归一化位置、激活与位置编码随模型而异，读论文时核对具体结构。

encoder 常允许双向上下文；decoder-only 语言模型通常使用因果注意力生成；encoder-decoder 将输入编码与输出生成分开，并可使用跨注意力。名称描述架构，不自动决定模型在所有任务上怎样调用。

本套 tiny LM 是教学用的一层因果注意力模型，包含 embedding、位置、残差、归一化、前馈层和输出头；规模很小，采用字符级动作语料。它不复现 GPT、LLaMA 或任何具体论文的训练效果。

9.6 下一 token 目标与错位标签

序列 [a,b,c,d] 可构造输入 [a,b,c]，标签 [b,c,d]。训练时每个位置用此前前缀预测下一项。标签既要错开一位，注意力还要阻断未来，否则输入位置里可能直接包含答案信息。

若 logits 是 (B,T,V)，类别索引标签为 (B,T)，可以展平为 (BT,V) 和 (BT,) 计算交叉熵。若存在 padding 或只训练回答部分，还要按明确规则 mask，并按有效 token 数归一化。

有些现成语言模型内部自动 shift，手写训练代码若再 shift 一遍会错两位。不要根据变量名猜，取一条短序列逐位打印输入和标签核对。

9.7 Teacher forcing 与生成

训练通常把参考前缀作为输入，称 teacher forcing。生成时模型的输出加入后续前缀，之前的错误可能影响之后分布。这是训练条件与滚动生成条件的一项差异。

生成循环是：编码已有前缀；取最后位置 logits；按 greedy 或采样选下一 token；追加；遇 EOS 或达到长度预算停止。使用 eval 和 no_grad；随机采样时记录温度、种子与采样规则。只展示一条好样例不足以支持稳定生成能力。

教学语料重复少量动作行，loss 降低和生成结构看起来合理只证明机制跑通；没有足够的独立任务评测，不能声称组合泛化或智能体控制性能。

9.8 复杂度、表示与后续阅读

标准全注意力 scores 的空间开销随 T² 增长。实际系统有缓存、优化内核与不同注意力设计；基础阶段先理解张量，不急于实现高性能 GPU 内核。CS336 的完整作业适合后续在 Python、DL 和系统基础更稳后选做。

权重由Q与K决定，被平均的是V。若所有V都相同，不同权重也可产生相同输出；看到输出相同不能直接断言注意力权重相同。反过来，权重和为1也只证明归一化形式，不证明模型语义正确。

softmax的稳定计算

对分数[1000,1001]直接exp可能溢出，先减最大值变为[-1,0]，得到相同概率。对被屏蔽位置填-inf；如果整行都被屏蔽，分母可能失去定义。padding与causal的组合需要确保有效query仍有合法key。

训练语料中的动作行可以有很低的语言损失，但模型生成的顺序可能在当前环境不合法。比如pickup前方没有物体、open时没有钥匙，都是语言文本之外的条件。将文本拼出来与完成任务，需要两层不同检查。

import math
import torch

def causal_attention(Q, K, V):
    if Q.ndim!=3 or K.shape!=Q.shape or V.ndim!=3:
        raise ValueError("invalid ranks or Q/K shape")
    if Q.shape[:2]!=V.shape[:2] or Q.shape[-1]==0 or Q.shape[1]==0:
        raise ValueError("incompatible dimensions")
    T = Q.shape[1]
    scores = Q @ K.transpose(-2,-1) / math.sqrt(Q.shape[-1])
    mask = torch.ones(T,T,device=Q.device,dtype=torch.bool).triu(1)
    weights = scores.masked_fill(mask,float("-inf")).softmax(-1)
    return weights @ V, weights

10.1 先区分基础模型、训练与系统

语言模型根据上下文预测 token。模型训练改变参数；一次推理根据现有参数产生输出；Agent 系统则将模型置于可与环境反复交互的流程中。一个 Agent 可以完全不更新模型参数，也可以包含学习模块。

你用 AI 助手写好一个固定策略，再运行它，是 AI 辅助编程。实验中被评测 Agent 自己读取观察、调用工具并选择动作，是智能体行为。二者都能有用，但记录和论文叙述要分清。

10.2 SFT 的目标

监督微调使用输入与参考输出样例，通过目标 token 的负对数概率训练。若只训练回答部分，提示和 padding 需要相应 loss mask。训练数据可能来自人工、程序或其他模型，质量和覆盖会影响结果。

SFT 可以教输出格式、工具调用和常见决策模式，但“训练集回答更像示例”不等于未见任务更强。对新组合的评估需要独立划分与基线。

10.3 偏好优化、奖励和策略梯度

DPO 的典型数据包含同一提示下的较好/较差回答，并相对于参考策略构造偏好训练目标；不需要像 PPO 那样显式执行同一种在线采样更新流程。标签偏好本身仍可能有误，不能认为方法名保证正确。

策略梯度从期望回报目标出发，使用与 log pi(a|s) 梯度相关的估计更新策略。奖励信号不必是“正确下一 token”，可以来自终局成功、验证器或奖励模型；若奖励设计错误，优化可能强化非预期行为。

PPO 常通过旧策略与新策略概率比、优势估计及裁剪代理目标限制某些更新幅度。概率比裁剪与第 5 章梯度范数裁剪不是一件事；PPO 的具体实现也有值函数、KL、采样等多项设计。

GRPO 的典型形式对同一问题采样一组回答，以组内奖励构造相对优势，再进行受约束策略更新，常不使用与标准 PPO 相同的独立 value model。组内奖励全部相同可能缺少相对信号；实际变体的归一化和 KL 计算需要按论文/实现核对。

PPO 采样轨迹、奖励、优势等 回报与优势怎么定义，更新受何种约束
GRPO 同题多输出的奖励组等 组怎样形成，奖励无差异时发生什么

现在先画数据流，不需要把四种方法都实现一遍。表格 Q-learning 的“max Q 目标”也不是这些语言模型后训练算法的统一实现。

10.4 多模态：ViT、VLM、VLA

ViT 将图像划为 patch，形成一组表示后使用 Transformer；VLM 将视觉信息与语言机制结合，可以理解或生成与视觉相关的文本；VLA 进一步把动作作为关键输出或控制表示。它们不是相互完全包含、只有一套实现的固定产品类别。

像素编码器、语言规划器、低层控制器可能来自不同模型。用文字版 MiniGrid 做实验时省去了很多感知问题，不能把同样结果直接搬到 VLA 机器人控制结论中。

一个 open_door 技能可以声明前置条件“门在前方、若上锁则持对应钥匙”，执行若干原始动作，终止于观察到门已打开或明确失败。只返回字符串“成功”不够，环境状态或允许观察应提供可核查结果。

10.6 代码式策略及抽象层级

Code as Policies 提供了把模型生成程序用于控制接口组合的经典研究入口。学习时重点追踪自然语言命令如何变成程序，以及程序依赖哪些人工提供的感知和动作能力。

例如模型生成 move_to_seen(key); pick_up(); move_to_seen(door); toggle()，短短四个调用可能背后隐藏路径规划、对象定位和控制。把人工封装能力更强的接口与原始转向/前进动作比较，结果包含了接口设计的帮助，不能都归因于模型推理。

因此第一轮可用不同抽象接口诊断困难来源；检验新技能选择机制时，再统一技能集合、观察和预算。每个技能展开多少动作、失败如何返回、何时可中断，都要记录。

10.7 可执行动作与程序边界

入门实践先使用受限动作列表或结构化 JSON，固定操作白名单、参数类型、最大长度和执行预算。不要直接把任意模型字符串交给宿主 Python 的 exec。真正通用代码式策略需要专门的隔离执行设计和资源限制，超出本章最小接口练习。

例如 {"action":"forward"} 可解析成环境枚举；{"skill":"goto","target":"observed-door-1"} 只允许引用已观察对象。解析错误、非法动作、技能超时和模型超预算都保留为结果。这样的接口既便于调试，也能检查方法究竟看到了什么。

Memory、Skill和Harness怎样划分

Memory记录见过什么、何时见到、现在可能是否过时；Skill定义可复用行为、前提与终止；Harness负责模型交互、工具路由、上下文、预算和记录。名称不是固定标准，自己的实现可以不同，但论文图中的每条箭头应有具体输入输出。

后训练为什么不是当前第一步

如果错误来自观察转换泄漏、技能返回值错误或评分器不可靠，增加SFT/RL训练可能只是让系统更强地适应错误目标。先确认任务和基线，才知道训练信号应优化什么。

预算必须跨模块求和

一次技能选择可能含规划、诊断、重试与总结四次模型调用。若只统计最后一条动作，就低估了成本。技能开发/发现成本与测试推理成本可以分开报告，但不能在总投入比较中隐去前者。

import json

def parse_action(text, seen_ids):
    try:
        obj = json.loads(text)
    except (json.JSONDecodeError,TypeError) as exc:
        raise ValueError("invalid JSON") from exc
    if not isinstance(obj,dict) or set(obj)!={"action","target"}:
        raise ValueError("invalid fields")
    action,target = obj["action"],obj["target"]
    if action=="forward" and target is None:
        return action,target
    if action=="toggle" and isinstance(target,str) and target in seen_ids:
        return action,target
    raise ValueError("unknown action or invalid target")

11.5 失败分析怎么做

从具体轨迹向原因推进，不只给一句“推理不行”。可以先分：格式或接口失败；观察理解错误；历史状态丢失；技能前提不满足；路径/动作执行错误；预算耗尽；评分或记录故障。分类允许“尚无法判断”，避免为了整齐而过度归因。

例如 Agent 连续 toggle 锁门：先查它是否观察到锁和钥匙，是否持正确钥匙，技能前提是否检查，模型是否收到上次失败反馈。不同原因对应不同改进，单看终局失败无法区分。

人工挑选典型案例用于解释机制，但总体指标必须覆盖所有任务。若新增机制只在人工挑出的失败子集有效，要同时报告全部样本和正常任务的退化情况。

之后再决定任务规模与冻结测试。不能因为开发集表现不好就不断换掉难题；改变任务选择依据要留下记录。真实模型费用需在执行前具体估算与获得授权，当前HTML中的练习不会自动启动调用。

一个样本如何被复查

读者应能从episode_id找到配置、原始请求、响应、解析动作、每步允许观察与终止原因，再用独立评分规则重算成功。若记录里只有一句“运行成功”，他无法判断模型是否拿到了隐藏信息、是否有超预算重试或是否误判成功。

消融的含义

完整系统改善后，分别去掉前提检查、历史记忆或额外诊断调用，比较变化。每次去掉模块可能同时改变调用预算和信息量，因此要设计预算匹配或额外对照。消融不是把系统随意弄坏后证明“模块重要”。

如何解释没有提升

可能基线已接近上限、任务对所研究能力不敏感、改动不正确、样本太少或成本抵消收益。先检查实现与公平条件，再决定是否修方法或换研究问题。保留原先假设与预测，避免看到结果后重写故事。

学期末应能展示的东西

一个可运行基线、一条能够逐步讲清的成功轨迹、一条能够定位原因的失败轨迹、一份公平对照表、相关工作差异和一个有依据的下一问题。图表和汇报应由真实记录产生。对暂时没跑的依赖与模型明确标记，不用预期结果填空。

实现配对成功比较

核心

实现paired_summary(a,b)，a/b为等长bool列表；返回n、both、a_only、b_only、neither、delta，delta为B-A成功率差。空输入delta为None，拒绝长度不等与非bool。

验收：用含所有四类配对的样本手算核对；说明这不是统计显著性检验。

提示

逐任务配对计数；delta=(b_only-a_only)/n。

参考解答
python
def paired_summary(a, b):
    if len(a)!=len(b) or any(type(v) is not bool for seq in (a,b) for v in seq):
        raise ValueError("expected equal-length boolean sequences")
    both = sum(x and y for x,y in zip(a,b))
    a_only = sum(x and not y for x,y in zip(a,b))
    b_only = sum(y and not x for x,y in zip(a,b))
    n = len(a)
    return dict(n=n,both=both,a_only=a_only,b_only=b_only,
                neither=n-both-a_only-b_only,
                delta=(b_only-a_only)/n if n else None)
