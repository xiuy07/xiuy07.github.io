# 编译、输入输出与类型

## 先完成一个闭环

这一章的目标是：把源文件编译成可执行文件，输入数据，核对输出。先确认 `g++ --version` 能显示版本，再运行 `python practice/judge.py p01`。编辑器负责写字，编译器负责检查和生成程序；保存文件不等于重新编译。

一个普通 C++ 程序从 `int main()` 开始。`#include <iostream>` 引入流的声明；`std::cin >> x` 读取一个值，`std::cout << x` 输出一个值。题目没有要求的提示文字不要输出，否则本地测试也会判错。

```text
g++ -std=c++17 -O2 -Wall -Wextra -pedantic main.cpp -o main
```

Windows PowerShell 中用 `./main.exe` 运行；Linux/macOS 中用 `./main`。我们的评测器会完成编译和输入重定向，暂时不必手动拼命令。

## 先判断范围，再选择类型

`int` 的具体宽度由实现决定，常见环境为 32 位；本项目编译环境如此。`long long` 至少有 64 位，适合累计到约 10¹² 的整数。乘法在赋值前就发生，因此 `long long area = a * b;` 仍可能先在 `int` 中溢出；应写 `1LL * a * b` 或先让一个操作数为 `long long`。

有符号整数溢出是未定义行为。不要根据某次运行“绕回负数”来推导答案。整数除法向零截断，`7 / 2` 是 `3`；需要小数时让操作数成为浮点数。浮点数常不能精确表示十进制小数；金额练习统一使用整数“分”。

`-1` 与无符号数比较可能先转换成很大的无符号数。索引和长度混合运算时尤其要小心；本指南在边界计算中会明确转换到合适的有符号类型。

## 从报错定位阶段

| 表现 | 先检查什么 |
|---|---|
| 缺分号、未声明名称 | 当前源文件的语法与 include |
| undefined reference | 只有声明没有定义，或漏编译了实现文件 |
| multiple definition | 非 inline 定义被重复放进多个翻译单元 |
| 能编译但测试错误 | 输入格式、边界、类型和算法 |

预处理处理 include 与宏，编译/汇编生成目标文件，链接连接定义。`inline` 的重要语言作用是允许满足规则的重复定义；它不保证机器码一定展开。

## 代码实验：让乘法在正确类型中发生

```cpp
#include <iostream>
#include <limits>
int main() {
    int a = 50000, b = 50000;
    std::cout << 1LL * a * b << '\n';
    std::cout << 7 / 2 << ' ' << 7 / 2.0 << '\n';
    std::cout << (std::numeric_limits<long long>::digits >= 63) << '\n';
}
```
