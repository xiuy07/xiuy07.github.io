# 哈希、双指针与滑动窗口

## 读题与方法选择

看到数组先问四件事：是否有序、是否要求连续、是否允许修改输入、是否需要返回下标。两数和的哈希保留原下标关系；三数和先排序能使用双指针，但会改变原顺序；最长无重复片段要求连续，不能排序。

哈希表的“平均 O(1)”依赖散列分布，并非最坏情况保证。一般机试可使用 unordered_map 并合理 reserve；对抗输入或稳定时限要求高时，可考虑排序 O(n log n) 的替代解。面试时要主动说明这个取舍。

## 状态与不变式

窗口是当前正在维护的一个区间，不是看到“双指针”就能套用。无重复窗口中，右端添加字符后，合法性可以通过只右移左端恢复；全部元素非负时，“和不超过 K”也常能这么做。若允许负数，右移端点不再单调改变和，通常应考虑前缀和与哈希。

## 手推一遍

在 abba 上手推：r=0 得到 a，r=1 得到 ab，r=2 的 b 上次在 1，所以 l=2，窗口为 b。最后 a 上次在 0，但 l 不能退回 1，应保持 max(2,1)=2，窗口为 ba，答案 2。

统计配对时，序列 [2,2,2]、K=4：查询得到 0、1、2，累计 3。先插入再查询会得到 1、2、3，错误统计自己与自己配对。

## 从实现到证明

以 [p65 和为目标的配对数量](#problem/p65) 为例：

枚举两层循环需要 O(n²)。从左向右扫描，用哈希表记录已经出现的数及次数，先查询 K-x，再把 x 加入表。

正确性：处理 x 前，表中恰好是左侧元素。因此新增计数恰好对应右端点为当前位置的合法对，每一对只计算一次。

复杂度：期望 O(n) 时间、O(n) 空间。

易错点：先插入再查询会把自己配给自己；答案必须用 long long。

<details><summary>完整 C++17 参考实现</summary>

```cpp
#include <iostream>
#include <unordered_map>
using namespace std;
using ll = long long;
int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    ll k, x, ans = 0;
    cin >> n >> k;
    unordered_map<ll, ll> f;
    f.reserve(n * 2 + 1);
    while (n--) {
        cin >> x;
        auto it = f.find(k - x);
        if (it != f.end())
            ans += it->second;
        ++f[x];
    }
    cout << ans << '\n';
}
```

</details>

## 升学与面试追问
