# 综合练习与可维护的小工程

## 先写契约，再写实现

一个可测试的小工程需要明确输入、输出、状态和失败方式。把“支持缓存”细化为：容量是否可能为零？更新已有键算不算访问？get 未命中返回什么？键值允许哪些范围？这些问题决定测试，而不是写完程序后再猜。

本指南最后两题选择 MinStack 与 LRU。前者练习在栈状态中维护辅助最小值，后者练习 list 与哈希表的协作。它们可以用标准库实现，重点在状态一致性和接口，而不是手写一切底层内存。

## MinStack 的不变式

每个栈结点保存 `(当前值, 到这一层为止的最小值)`。push 时用新值与旧最小值取 min；pop 同时移除这两个信息。重复最小值是重要边界，不能简单地“弹出一个最小值后就删除所有相同值记录”。

## LRU 的两份索引

链表按最近使用顺序保存键值对，哈希表把键映射到链表迭代器。每次命中把结点移动到前面；超容量从尾部淘汰，同时删除哈希表记录。list 的 splice 可以在同一链表内移动结点而不复制值。

默认复制含有“指向自身 list 的迭代器”的缓存类可能出错，因为复制后的哈希表迭代器仍指向旧容器。这个练习只创建一个缓存，不要求复制；若把它做成通用组件，应明确删除复制或重新建立索引。

## 测试要攻击假设

先准备最小输入、空状态、单元素、重复值、负数、边界范围，再准备随机序列。可以对小规模数据写慢但清晰的模型，与高效实现对拍。测试通过说明这些用例符合契约，不自动证明复杂度，也不代替内存检查。

本地评测保留每行边界，帮助发现多输出/少输出。WA 时先看差异和输入，再缩小成最小失败用例；CE 先修第一条涉及自己代码的编译错误；RE 检查异常、越界和生命期；TLE 检查循环推进与复杂度。

## 代码实验：维护前缀最小值

```cpp
#include <algorithm>
#include <iostream>
#include <utility>
#include <vector>
int main() {
    std::vector<std::pair<int,int>> st;
    for(int x:{4,2,2,7}) {
        int m=st.empty()?x:std::min(x,st.back().second);
        st.push_back({x,m});
    }
    std::cout << st.back().second << '\n';
    st.pop_back(); st.pop_back();
    std::cout << st.back().second << '\n';
}
```
