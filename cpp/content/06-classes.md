# 类、初始化与析构

## 类要维护一个明确规则

封装的目的，是让每个公开操作都能保持对象有效。例如账户余额不能为负：构造时检查初值，存款检查金额，取款先验证余额再修改。成员设为 private 能限制访问，但仍需要正确的接口逻辑。

struct 与 class 都能定义成员函数、构造函数和虚函数。它们的区别包括两项默认规则：struct 默认成员访问和默认继承方式为 public，class 两者默认为 private。明确写出访问说明后，两者能表达相同的类机制。

## 初始化不是构造函数体内赋值

进入构造函数体前，基类和成员已经初始化。`const` 成员、引用成员、没有默认构造函数的成员对象，需要在适当的初始化位置取得初值，例如成员初始化列表；允许的类内成员初始值也可参与初始化。不能等到函数体里再给 const 成员赋值。

实际顺序由规则决定：虚基类、直接基类、非静态数据成员，然后构造函数体。成员按声明顺序初始化，不按初始化列表书写顺序。把列表写成与声明一致的顺序，避免误读与警告。

## 析构按相反方向收尾

局部对象在正常离开作用域时逆构造顺序析构。一个对象析构时先执行自己的析构函数体，再销毁成员和基类子对象。若构造函数抛出，已经构造完成的子对象会被销毁，未完成构造的整个对象不会调用自己的析构函数。

RAII 就是把资源释放责任交给一个对象的析构。这样 return、正常离开和异常栈展开都能走同一条清理路径。析构函数不应让异常逃逸。

## 代码实验：顺序由声明决定

```cpp
#include <iostream>
#include <string>
struct Trace {
    std::string name;
    explicit Trace(std::string s):name(s) { std::cout << '+' << name << '\n'; }
    ~Trace() { std::cout << '-' << name << '\n'; }
};
struct Pair {
    Trace a;
    Trace b;
    Pair():a("a"),b("b") { std::cout << "body\n"; }
    ~Pair() { std::cout << "~Pair\n"; }
};
int main() { Pair p; }
```

<details><summary>查看已验证的运行输出</summary>

```text
+a
+b
body
~Pair
-b
-a
```

</details>

本机运行：`python practice/judge.py demo d06`。源码位于 `demos/d06.cpp`。

a 和 b 按声明顺序构造；退出时先运行 Pair 的析构函数体，再按 b、a 的顺序销毁成员。输出不是因为“栈先进后出”的口号，而是对象生命期规则。

## 隐式成员不是无条件全都可用

常说的六个特殊成员是默认构造、析构、拷贝构造、拷贝赋值、移动构造和移动赋值。但是否隐式声明、是否被删除以及是否参与调用有条件。例如自行声明析构函数会影响隐式移动成员的生成；含 unique_ptr 的类默认不能拷贝。

优先组合 string、vector 等资源管理成员，让编译器完成正确行为，这叫零法则。只有直接拥有裸资源时，才需要认真实现拷贝/移动协议。
