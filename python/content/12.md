# 12 并发与性能边界

线程、进程与 async 的适用场景

学习目标：按任务瓶颈选择并发工具，并保留输入输出顺序。

## 先判断在等什么
I/O 密集任务常在等待文件、网络等资源，线程能让等待重叠；CPU 密集的纯 Python 计算在普通启用 GIL 的 CPython 中通常不能靠线程获得多核加速，可考虑进程。NumPy 计算、释放 GIL 的扩展以及可选 free-threaded 构建需要单独评估，不能把 GIL 当作所有 Python 环境的统一结论。

asyncio 使用协作式调度，await 把控制权交还事件循环；异步函数内直接调用阻塞操作仍会阻塞整个循环。并发不是自动加速，任务创建、数据传输和同步都有成本。

## 顺序和异常也是接口的一部分
Executor.map 的结果按输入顺序返回；as_completed 按完成顺序返回，若要恢复原顺序必须记录索引。异常在取结果时重新抛出，因此不要只提交任务而不检查 future。

共享可变状态需要同步，GIL 不替代业务层锁。进程入口用 main 保护，提交的函数定义在模块顶层，注意可序列化约束。不要用并发来掩盖一个原本 O(n²) 的算法。

## 运行示例

```python
from concurrent.futures import ThreadPoolExecutor
def square(x):
    return x * x

if __name__ == "__main__":
    with ThreadPoolExecutor(max_workers=2) as pool:
        results = list(pool.map(square, [3, 1, 2]))
    print(results)
```

预期输出

```text
[9, 1, 4]
```

示例只展示提交与结果顺序，计算太小，不用于证明性能提升。with 保证退出时等待任务完成并释放执行器。

运行：`python demos/12.py`

## 手推与修改

如果三个任务依次耗时3、1、2秒，map 和 as_completed 的结果顺序分别如何？

## 易错点

不要把线程数越多等同于越快；不要忘记消费 future 才能观察异常。
