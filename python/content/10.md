# 10 模块、类型与工程习惯

组织代码、测试和可复现环境

学习目标：让脚本可以被导入、测试和重复运行。

## 导入会执行模块顶层
首次 import 通常会执行模块顶层代码并缓存模块对象。把命令行入口放进 `if __name__ == "__main__":`，导入时仅定义函数和类。避免把文件命名为 json.py、typing.py 或 pandas.py，防止遮蔽依赖。

按职责分开：读写层负责路径和格式，计算层只接收值并返回结果，入口解析命令行参数。这样计算测试无需真正读写文件。包内导入要有清晰的运行方式；工程代码优先 `python -m package.module`。

## 类型注解与测试互补
注解描述预期形状，静态检查发现部分错误；测试验证具体行为，两者都不能证明程序绝对正确。先写有代表性的边界：空列表、0、负数、重复值、Unicode、非法输入。断言要检查结果和不应变化的输入。

## 最小工程闭环
保持 snake_case 命名、4空格缩进、小函数和明确返回值。依赖记录在 requirements 或 pyproject，复现实验再记录实际安装版本。可选工具 `ruff check .`、`ruff format --check .`、`python -m pytest`；本学习包评测器只用标准库，不要求这些工具。

## 运行示例

```python
def mean(values: list[float]) -> float | None:
    if not values:
        return None
    return sum(values) / len(values)

def main():
    assert mean([]) is None
    assert mean([0, 2, 4]) == 2
    print("3 values ->", mean([0, 2, 4]))

if __name__ == "__main__":
    main()
```

预期输出

```text
3 values -> 2.0
```

导入时不运行 main。空输入的返回规则写在类型中，并通过断言检查；没有使用0作为空值标记。

运行：`python demos/10.py`

## 手推与修改

## 易错点

不要把工作目录当成代码目录；不要把类型检查通过当成业务测试通过。
