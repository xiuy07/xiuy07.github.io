# 19 多表连接与完整性

merge、concat、键与匹配校验

学习目标：在连接前后检查行数，避免悄悄重复计算。

## 连接回答什么问题
merge 按键匹配：left 保留左表所有行，inner 只保留双方匹配行。concat 沿轴拼接，常用于同结构多月文件，不是按业务键查找。join 类型由分析问题决定，不应根据“哪个运行后没有缺失”来挑选。

## 键的重复会放大行数
左表某键有m行，右表同键有n行，会产生m×n行。订单明细连接用户表通常要求 many_to_one：订单可重复用户id，用户表id必须唯一。`validate="many_to_one"` 能尽早发现维表重复，`indicator=True` 展示匹配状态。

## 缺失键也要检查
pandas merge 中双方空键可能互相匹配，这与常见SQL的NULL行为不同。重要业务键通常应先检查非空和唯一性。左右列名冲突要明确 suffixes，避免之后选错字段。

连接后核对总行数、未匹配行数及金额总和。如果只需映射一列，也可使用 Series.map，但依然需要右侧映射键唯一。多表分析先画清每张表一行代表什么，再写代码。

## 运行示例

```python
import pandas as pd
orders = pd.DataFrame({"user": [1, 2, 1], "amount": [10, 20, 5]})
users = pd.DataFrame({"user": [1, 2], "city": ["A", "B"]})
joined = orders.merge(users, on="user", how="left", validate="many_to_one", indicator=True)
print(joined.groupby("city")["amount"].sum().to_dict())
print(joined["_merge"].astype(str).tolist())
```

预期输出

```text
{'A': 15, 'B': 20}
['both', 'both', 'both']
```

订单表一行一笔订单，用户表一行一个用户，所以 many_to_one 合理。匹配后城市A金额合计15。

运行：`python demos/19.py`

## 易错点

不要未核对键唯一性就连接；不要用连接后去重补救重复聚合。
