## 先问：函数回来了，局部名字去哪了

这个例子把内部函数返回出去。之后调用它，仍然能使用定义时外层的名字。

### 先猜一猜：外层函数返回后，rate从哪里取？

先在纸上写出输出，再运行这段代码。

```python
rate = 100
def make_scale(rate):
    def scale(value):
        return value * rate
    return scale

triple = make_scale(3)
rate = 200
print(triple(4))
```

<details class="checkpoint" markdown="1">
<summary>展开结果与逐步解释</summary>

```text
12
```

make_scale(3)建立自己的调用环境，其中rate=3。内部scale在这个环境中定义，之后查找自由变量rate时沿定义环境查找。修改全局rate不改变外层调用里的那个rate。

</details>

本例可单独运行：`python demos/features/21-closure-read.py`。

## 一次调用与一次定义分别做什么

执行def时，建立函数对象并把名字绑定到它；调用时，才根据实参建立局部环境、执行函数体。这里用“环境框”作为理解模型，不把它当成Python内部实现的全部细节。

| 环境 | 保存的绑定 | 外层环境 |
|---|---|---|
| 模块环境 | make_scale、triple、全局rate | 内建环境 |
| make_scale的这次调用 | rate → 3、scale → 内部函数 | 模块环境 |
| scale的这次调用 | value → 4 | 定义scale时所在的外层调用 |

**查名字沿定义环境；返回值沿调用过程交回。** 两个方向不要混淆：是谁调用了函数，不会临时改写函数自由变量的查找规则。

普通函数体中，如果某个名字有赋值且没有global/nonlocal声明，它通常被视为该函数的局部名字；即使赋值写在后面，前面的读取也可能触发UnboundLocalError。类体、推导式和其他特殊作用域还各有规则，不要把简化图当作所有语法的完整规范。

## 高阶函数：接收函数，或返回函数

可以把一次计算中的“怎么处理每个元素”作为参数。例如一个累加过程接收term，就能累加平方、绝对值或另一种量。传入 `abs` 是传对象；传入 `abs(-3)` 则已经算完，传的是3。

### 先猜一猜：为什么组合函数要先算里面，再算外面？

先在纸上写出输出，再运行这段代码。

```python
def compose(outer, inner):
    return lambda x: outer(inner(x))

def add_two(x):
    return x + 2

def times_three(x):
    return x * 3

print(compose(times_three, add_two)(4))
print(compose(add_two, times_three)(4))
```

<details class="checkpoint" markdown="1">
<summary>展开结果与逐步解释</summary>

```text
18
14
```

第一行先4+2，再乘3；第二行先4×3，再加2。compose返回的是一个新函数，最后的(4)才调用它。lambda只容纳一个表达式，复杂逻辑优先使用具名def。

</details>

本例可单独运行：`python demos/features/21-compose.py`。

## nonlocal：明确修改哪个外层绑定

闭包可以只读取外层名字；需要重新绑定外层名字时，写nonlocal。它寻找最近的、已经存在相应绑定的外层函数作用域，不用于修改模块全局变量。修改外层列表的内容与重绑列表名字也要区分：前者通常不需要nonlocal。

状态有用，也让函数结果依赖调用历史。为每个计数器单独调用一次工厂，得到独立状态；给同一个计数器再起别名，得到的仍是共享状态。

## 延迟绑定：闭包通常读的是名字，不是定义时快照

### 先猜一猜：循环里的三个函数会记住三个不同的i吗？

先在纸上写出输出，再运行这段代码。

```python
late = [lambda: i for i in range(3)]
fixed = [lambda i=i: i for i in range(3)]
print([f() for f in late])
print([f() for f in fixed])
```

<details class="checkpoint" markdown="1">
<summary>展开结果与逐步解释</summary>

```text
[2, 2, 2]
[0, 1, 2]
```

第一组共享推导式里那个i的绑定，调用时循环已经结束，读到2。第二组利用默认参数在每次创建函数时求值，给各函数保存独立默认值。这个技巧来自默认值规则，不是lambda的特殊记忆能力。

</details>

本例可单独运行：`python demos/features/21-late-binding.py`。

## 自己画一次环境图

为下面的完整示例画出两个工厂调用，再画三次add调用。只需记录start、total、step与返回值。之后打开[交互实验](../index.html#lab)，逐步对照“闭包保存环境”。

## 完整运行示例

```python
def make_counter(start):
    total = start
    def add(step):
        nonlocal total
        total += step
        return total
    return add

a = make_counter(10)
b = make_counter(100)
print(a(2), a(3), b(1))
```

预期输出

```text
12 15 101
```

运行：`python demos/21.py`。
