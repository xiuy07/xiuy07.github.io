# 04 容器与哈希思维

列表、元组、集合、字典

学习目标：根据访问方式选择容器，写出清晰的计数与查找。

## 从一个小问题开始

### 先决定“保留什么”，再选容器

想保存次序，用列表；只关心是否出现，用集合；要从名字找到次数，用字典。一个问题可能同时需要两个容器：用集合快速判断见没见过，用列表保留首次出现顺序。

### 先猜一猜：解包、字典合并和排序会修改原对象吗？

先在纸上写出输出，再运行这段代码。

```python
first, *middle, last = [10, 20, 30, 40]
print(first, middle, last)
base = {"theme": "light", "size": 18}
override = {"size": 20}
print(base | override)
values = [3, 1, 2]
result = values.sort()
print(values, result)
```

<details class="checkpoint" markdown="1">
<summary>展开结果与逐步解释</summary>

```text
10 [20, 30] 40
{'theme': 'light', 'size': 20}
[1, 2, 3] None
```

星号目标middle接收一个列表。字典竖线合并产生新字典，同名键用右侧值，base保持原状。sort则直接修改values；返回None是提醒你它属于原地操作。

</details>

本例可单独运行：`python demos/features/04-container-idioms.py`。

**特性补充：** 字典的 `get(key, default)` 不插入键；`setdefault(key, default)` 在键不存在时插入。统计频次可用Counter，收集同组元素可用defaultdict。先让普通字典版本工作，再选择更简洁的工具。


## 四种容器如何选
list 是有序可变序列，适合按位置访问；tuple 表达固定结构；set 适合去重和成员判断；dict 把键映射到值，并保持插入顺序。集合不承诺遍历顺序，需要稳定输出时显式排序。

字典键和集合元素必须可哈希。列表不能做键；只包含可哈希元素的元组可以。相等对象必须有相同哈希，反过来不成立。不能把“哈希相同”当作“对象相等”。

## 常见复杂度
list 尾部 append 均摊 O(1)，头部插入 O(n)；排序 O(n log n)，成员判断 O(n)。dict/set 查找平均 O(1)，极端碰撞会变慢。队列头部频繁取出使用 collections.deque，不要反复 pop(0)。

## 从两层循环到一次扫描
找两数和时，为每个新数 x 查询 target-x 是否已经出现；查到后才能把 x 的位置记入表，以免重复使用当前元素。重复值并非例外：两个不同位置的相同数可以组成答案。

`sorted` 返回新列表，`list.sort` 修改原列表并返回 None。多关键字排序用元组 key，例如 `(-score, name)` 表示分数降序、姓名升序。

## 运行示例

```python
from collections import Counter
words = ["pear", "apple", "pear", "banana", "apple", "pear"]
counts = Counter(words)
rank = sorted(counts.items(), key=lambda item: (-item[1], item[0]))
print(rank)
print(list(dict.fromkeys(words)))
```

预期输出

```text
[('pear', 3), ('apple', 2), ('banana', 1)]
['pear', 'apple', 'banana']
```

Counter 计算次数；元组排序把频率相同的词按名称排序。dict.fromkeys 按首次出现顺序去重。

运行：`python demos/04.py`
