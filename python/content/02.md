# 02 名字、对象与可变性

从 C++ 的变量切换到 Python 语义

学习目标：分清重新绑定、原地修改、浅拷贝和相等。

## 从一个小问题开始

### 先画箭头，再读赋值语句

读 `a = value` 时，先说“让名字a指向右边的对象”。这样读，后面的函数参数、闭包和容器复制就能使用同一套解释。

| 语句 | 是否新建外层列表 | 是否修改原列表 |
|---|---|---|
| `b = a` | 否 | 否，只增加一个名字 |
| `b = a.copy()` | 是 | 否，内部元素仍可能共享 |
| `b.append(9)` | 否 | 是，修改b当前指向的列表 |
| `b = [9]` | 是 | 否，只把b指向新列表 |

### 先猜一猜：append与加号看起来相近，为什么结果不同？

先在纸上写出输出，再运行这段代码。

```python
def change(xs):
    xs.append(3)
    xs = xs + [4]
    return xs

original = [1, 2]
result = change(original)
print(original)
print(result)
```

<details class="checkpoint" markdown="1">
<summary>展开结果与逐步解释</summary>

```text
[1, 2, 3]
[1, 2, 3, 4]
```

进入函数时，xs与original指向同一列表；append把3加进去。随后加号创建另一个列表，赋值只重绑局部名字xs。return把新列表交给result。original仍指向旧列表。

</details>

本例可单独运行：`python demos/features/02-mutation-binding.py`。

**特性补充：元组不可变到哪一层？** `t = ([1], 2)` 不能执行 `t[0] = [9]`，但可以执行 `t[0].append(9)`。元组保存的元素引用没有更换，那个列表本身仍可修改。“不可变容器”不保证内部对象也不可变。


## 名字指向对象
`a = [1, 2]` 创建列表并让名字 a 指向它；`b = a` 只增加一个指向同一对象的名字。`b.append(3)` 修改列表，a 也能看到；`b = [9]` 只是重新绑定 b。函数参数同样绑定到传入的对象，不能简单套用 C++ 的引用参数规则。

`==` 比较值，`is` 判断是否为同一对象。与 None 比较写 `x is None`；数值、字符串比较写 `==`。整数缓存和常量合并是实现细节，不能用它们推断业务语义。

## 类型与精度
Python 的 int 可增长到内存允许的规模；NumPy 的固定宽度整数不同。`bool` 是 int 的子类，统计时要意识到 True 可参与算术。`/` 得到浮点结果，`//` 向负无穷取整，`-7 // 3 == -3`，并非截断到零。

浮点数近似存储，0.1+0.2 通常不与0.3精确相等。近似数比较可用 `math.isclose`；金额需先约定整数分或 Decimal，而非临时多保留几位小数。

## 复制哪一层
`a.copy()` 或切片只复制外层；嵌套容器内部仍共享。`copy.deepcopy` 会递归复制多数常见对象，但并非所有外部资源都能复制。创建矩阵用 `[[0] * m for _ in range(n)]`，避免多行共享同一个列表。

## 运行示例

```python
a = [[1], [2]]
b = a.copy()
b[0].append(9)
b.append([3])
print(a)
print(b)
print(a is b, a[0] is b[0])
```

预期输出

```text
[[1, 9], [2]]
[[1, 9], [2], [3]]
False True
```

外层列表已分开，所以 append([3]) 不影响 a。第一行子列表仍共享，所以9同时出现在两边。

运行：`python demos/02.py`

## 易错点

不要使用 `[[0]*3]*2` 构造独立矩阵；不要依赖 `is` 比较整数的偶然结果。
