# 05 控制流与推导式

分支、循环、短路与边界

学习目标：明确每次循环维护的状态，避免边界错误。

## 从一个小问题开始

### 把条件写成你能读出来的一句话

例如“非缺失，而且在0到100之间”，可以写为 `score is not None and 0 <= score <= 100`。`and` 的短路让后面的比较只在score非缺失时执行。不要为了少写几个字，改变0和None的业务含义。

### 先猜一猜：or返回布尔值吗？推导式对应哪段循环？

先在纸上写出输出，再运行这段代码。

```python
print(0 or 99, None or 99, "ok" and 8)
values = [-2, 0, 3, 5]
compact = [x * x for x in values if x > 0]
expanded = []
for x in values:
    if x > 0:
        expanded.append(x * x)
print(compact, compact == expanded)
```

<details class="checkpoint" markdown="1">
<summary>展开结果与逐步解释</summary>

```text
99 99 8
[9, 25] True
```

or返回第一个真值操作数，或最后一个操作数；and返回第一个假值操作数，或最后一个操作数。推导式按“取x→筛选→求平方→收集”的顺序执行。

</details>

本例可单独运行：`python demos/features/05-truth-and-comprehension.py`。

## 条件表达式与短路
if 判断对象的真值。0、None、空容器都为假，但它们在业务上未必相同：合法数值0不能被 `x or default` 随意替换。and/or 返回操作数，不一定返回 bool。多个区间按互斥顺序写 elif。

range 的右端不包含；`enumerate` 给位置和值，`zip` 同步遍历。zip 默认遇最短输入停止，要求等长时用 `strict=True`。for 后的 else 只在没有 break 时执行，适合表达“全部扫描后仍未找到”。

## 推导式是变换，不是压缩比赛
`[x*x for x in nums if x > 0]` 表示先筛选再转换。复杂分支、日志、副作用应写普通循环。生成器表达式用圆括号，可以被 sum 消费而不保存所有中间结果。

## 栈为什么能匹配括号
最近打开的括号必须最先关闭，符合后进先出。遇左括号入栈，遇右括号比较栈顶，结束时栈必须为空。不需要为每个右括号从头寻找对应左括号。

## 运行示例

```python
def valid(text):
    stack = []
    pairs = {')': '(', ']': '[', '}': '{'}
    for char in text:
        if char in "([{":
            stack.append(char)
        elif not stack or stack.pop() != pairs[char]:
            return False
    return not stack

print(valid("([])"), valid("([)]"), valid(""))
```

预期输出

```text
True False True
```

输入限定为括号字符。`or` 的短路保证空栈时不会 pop；所有字符读完后仍需检查未闭合的左括号。

运行：`python demos/05.py`

## 手推与修改

逐步记录 ([)] 的栈，每次写出 char、stack 与是否提前返回。

## 易错点

不要在遍历列表时直接删除元素；不要把循环正常结束和 break 混为一谈。
