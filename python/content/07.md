# 07 迭代器、生成器与装饰器

惰性处理与函数包装

学习目标：理解一次遍历的消费过程，并保留包装函数的元信息。

## 可迭代对象与迭代器
list 可以多次获取迭代器；生成器对象本身是迭代器，消费后不会自动重来。`iter(obj)` 获取迭代器，`next(it)` 取下一项，耗尽时抛 StopIteration。yield 让函数暂停并保留局部状态，下次 next 从暂停处恢复。

生成器适合逐行读取日志和分块处理，不代表整个流程必然省内存：最后 list(generator) 仍会把全部内容装进内存。异常可能在消费时才发生，因此 try 范围应覆盖遍历过程。

## 装饰器就是重新绑定
`@decorate` 等价于 `f = decorate(f)`。包装函数接收 *args/**kwargs，调用原函数，再处理结果。使用 functools.wraps 保留 __name__、文档等元信息。缓存只适合结果由输入决定的函数，参数还需可哈希；不要缓存依赖隐含变化的外部状态。

闭包读取外层名字；延迟执行的函数可能看到循环结束后的值。确实要冻结当前值时可用默认参数捕获，先理解绑定时间再使用技巧。

## 运行示例

```python
from functools import wraps
def doubled(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        return 2 * fn(*args, **kwargs)
    return wrapper

@doubled
def total(values):
    return sum(values)

g = (x*x for x in range(4))
print(next(g), list(g), list(g))
print(total([1, 2, 3]), total.__name__)
```

预期输出

```text
0 [1, 4, 9] []
12 total
```

next 消费0；第一次 list 得到剩余的平方数；第二次为空。装饰后的 total 将原函数返回值翻倍。

运行：`python demos/07.py`

## 易错点

不要复用已消费的生成器；不要给有副作用的函数随意加缓存。
